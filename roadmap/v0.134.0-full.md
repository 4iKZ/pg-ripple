## v0.134.0 - Performance, Scale, and True Streaming Qualification

**Theme:** Complete the existing cursor-oriented query contract at the HTTP boundary and qualify it under realistic scale, memory, concurrency, timeout, and cancellation conditions.

> **Incremental effort:** 3-5 person-weeks for streaming, tests, evidence, and documentation. Existing v0.134 performance work remains in scope.

### Supported Surface

| Query form | Streaming requirement |
|---|---|
| `SELECT` | SPARQL Results JSON, CSV, TSV, and optional NDJSON |
| `ASK` | One standards-valid result |
| `CONSTRUCT` | N-Triples |
| `DESCRIBE` | N-Triples |
| SPARQL Update | Existing bounded response; no result stream |

SPARQL Results XML, Turtle, and JSON-LD may remain buffered because their existing serializers are document-oriented, but existing row and byte limits remain mandatory. Callers needing true graph streaming use N-Triples. NDJSON, if retained, is advertised only as `application/x-ndjson`.

### Execution Contract

- Replace all streaming-path `Client::query()` calls with `query_raw()` or its typed `RowStream` equivalent.
- The response body directly polls the PostgreSQL row stream. Do not place a detached producer task ahead of an unbounded or large channel.
- A stream owns its database connection, read-only transaction, row stream, encoder state, cancel token, deadline, cleanup state, and metrics until completion.
- Begin with bounded `statement_timeout` and `idle_in_transaction_session_timeout` settings. Commit only after successful footer emission; otherwise cancel and roll back.
- Return a connection to the pool only when transaction and session cleanup are proven. Discard it when cancellation or cleanup cannot be confirmed.
- Make `/sparql` and `/sparql/stream` select the same execution path for streaming-safe formats, including replica routing and authorization.
- Add opaque query IDs and `X-Pg-Ripple-Streaming: true`; allow the HTTP server to select transfer framing.

Configuration must include bounded defaults and maximums for query timeout, stream idle timeout, chunk bytes, and maximum row bytes. A request may lower its deadline but cannot exceed the server maximum.

### Typed Result Contract

Add one internal representation for buffered and streaming output:

```rust
struct ResultBindingRow {
    values: BTreeMap<String, Option<RdfBindingValue>>,
}

enum RdfBindingValue {
    Iri(String),
    BlankNode(String),
    Literal {
        lexical: String,
        datatype: Option<String>,
        language: Option<String>,
    },
    Triple(Box<QuotedTripleBinding>),
}
```

Internal metadata must expose query form and projected variables before the first row so empty result sets have correct headers. Internal stream functions remain outside `api/stable-v1.json`.

### Encoder Requirements

- SPARQL Results JSON uses `serde_json` for every string and emits a valid envelope without trailing commas.
- CSV uses a standards-compliant writer; TSV uses SPARQL TSV term syntax rather than display strings.
- N-Triples uses the existing RDF serializer, one complete triple per line.
- Unsupported RDF-star/media-type combinations fail before stream headers.
- Standards formats terminate the body on an execution error after headers; they do not append a non-standard pseudo-error record.

### Cancellation and Observability

A cancellation guard obtains a PostgreSQL cancel token before query execution and is marked complete only after encoder and transaction completion. Body drop, deadline, idle timeout, shutdown, and encoder failure enqueue bounded cancellation work. Metrics distinguish these reasons and record cancellation failures and forced connection discards.

Prometheus coverage includes active streams, requests, rows, bytes, duration, first-byte latency, database/encoder errors, cancellation reasons, cancellation failures, and connection discards. Extension page and row counters must increment on real emission.

### Required Test Matrix

#### Encoder Unit Tests

- Zero, one, and multiple rows.
- IRI, blank node, plain/typed/language literal, RDF-star where supported, and unbound values.
- Quotes, commas, tabs, backslashes, newlines, Unicode, and control characters.
- Empty projected result metadata.
- Error before the first row and after one or more rows.
- Independent parsing or round-trip validation for every advertised format.

#### HTTP Integration Tests

| Gate | Scenario | Blocking assertion |
|---|---|---|
| `http-stream-format` | SELECT/ASK/CONSTRUCT/DESCRIBE; empty and typed results | Independent JSON, CSV, TSV, and N-Triples parsers accept output |
| `http-stream-first-byte` | Deliberately slow multi-row query | First row arrives before query completion |
| `http-stream-memory` | At least one million rows | Peak RSS stays within the accepted fixed envelope |
| `http-stream-slow-client` | Throttled reader | Buffering remains bounded and database polling follows demand |
| `http-stream-disconnect-cancel` | Client drops the body | Query disappears from `pg_stat_activity` within the accepted interval |
| `http-stream-timeout` | Local and replica query exceeds deadline | PostgreSQL work is canceled and the reason is recorded |
| `http-stream-pool-reuse` | Success, timeout, disconnect, and encoder failure | Next request sees no transaction or session leakage |
| `http-stream-shutdown` | SIGTERM with active streams | Streams drain or cancel according to the documented policy |

#### Extension and Migration Tests

- `regress-v0134-streaming` covers projected metadata, typed term descriptors, real row/page counters, and large iteration without collection.
- `migration-0133-to-0134` installs the required migration script and verifies fresh-install versus upgraded internal function/GUC availability.
- Existing migration-chain and schema-fingerprint checks remain blocking.

#### Performance Evidence

`benchmark-streaming` records time to first byte, rows per second, peak HTTP RSS, backend memory where measurable, cancellation latency, slow-client behavior, per-format throughput, and 1/10/100/500 concurrent streams. It runs alongside the existing small/medium/large and predicate-stress tiers. Existing 10% median/p95 and 15% peak-memory regression thresholds remain in force.

Every blocking job reports the number of assertions executed and uploads its raw evidence. Required jobs cannot use successful skip behavior, `continue-on-error`, or `|| true`.

### Release Propagation

- v0.135 reruns streaming, cancellation, and cleanup regression checks through `POST /sparql/bindings`.
- v0.136 external audit covers stream cancellation, deadlines, transaction cleanup, backpressure, output encoding, and resource exhaustion.
- v0.137 exercises large streams, slow clients, deliberate disconnects, deadlines, replicas, and restarts during the 72-hour qualification.

### Migration and Documentation

Create `sql/pg_ripple--0.133.0--0.134.0.sql`, even if generated extension SQL carries the internal functions and no catalog DDL is needed. Update the HTTP API, SQL query reference, limits, tuning, cancellation, metrics, and format documentation. Remove claims that SSE start/done events or buffered `Client::query()` behavior constitute result streaming.

### Exit Criteria

- Streaming-safe formats do not buffer complete results.
- Memory remains bounded as row count grows and under slow readers.
- Disconnects, deadlines, shutdown, and replica routing cancel PostgreSQL work correctly.
- Pool reuse is clean after every terminal path.
- Output passes independent parsers and preserves RDF term types.
- All named blocking jobs pass and current raw evidence is attached.
- The existing v0.134 performance and scale gates pass.
