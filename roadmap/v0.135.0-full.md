## v0.135.0 - Safe Application Query API and Compatibility Freeze

**Theme:** Add typed initial SPARQL bindings and opt-in use of the existing prefix registry, then freeze the complete SQL, HTTP, GUC, schema, error, and compatibility contract for v1.

> **Incremental effort:** 3-5 person-weeks for implementation, migration, security review, testing, evidence, and documentation. Existing v0.135 compatibility-freeze work remains in scope.

### Public SQL API

Add binding overloads while preserving the existing one-argument functions:

```sql
pg_ripple.sparql(query text, bindings jsonb) returns setof jsonb
pg_ripple.sparql_construct(query text, bindings jsonb) returns setof jsonb
pg_ripple.sparql_describe(query text, bindings jsonb, strategy text default 'cbd') returns setof jsonb
pg_ripple.sparql_cursor(query text, bindings jsonb) returns setof jsonb
```

Existing functions delegate with an empty binding map. Parameterized SPARQL Update is excluded from v1 and fails explicitly.

### Binding Contract

Input uses the W3C SPARQL Results JSON term representation. The top level is an object keyed by `name` or `?name`, normalized to `name`.

Supported v1 term types are `uri` and `literal`. A literal may specify a datatype or `xml:lang`, never both. Reject duplicate normalized names, invalid variables, null, unknown fields, non-absolute datatype IRIs, invalid language tags, blank nodes, RDF-star triples, bindings absent from query scope, more than 64 bindings by default, and values above the configured byte limit.

Add bounded GUCs for maximum initial-binding count and value bytes. HTTP body limits remain independently enforced.

### Algebra and SQL Contract

- Parse the query before applying values.
- Build a one-row VALUES/table algebra relation programmatically and join it at the root query pattern.
- Preserve bound variables through projection, including variables not used in a triple pattern when query scope allows them.
- Combine correctly with query-local VALUES, FILTER, OPTIONAL, UNION, MINUS, BIND, subqueries, aggregation, HAVING, paths, named graphs, and permitted SERVICE operations.
- Dictionary-encode RDF terms before SQL generation and supply them as typed SQL parameters.
- Never use `str::replace`, regex replacement, manual quoting, or binding-value concatenation in query or SQL text.

Compiled query metadata includes SQL, typed parameters, query form, projected variables, and the plan-cache key. The cache key includes normalized query, query form, ordered binding names and term/SQL types, prefix mode, registered-prefix generation when applicable, schema generation, and relevant GUCs. It excludes values.

### Prefix Registry Integration

Preserve strict standards behavior by default:

```text
pg_ripple.sparql_prefix_mode = 'strict'
```

Opt-in registered mode may fill only prefixes missing from the formal query prologue. Query-local declarations always win. Validated missing declarations are serialized in deterministic lexical order before normal parsing; strings, comments, IRIs, and expressions are never searched or replaced.

Harden `_pg_ripple.prefixes` with owner and timestamp columns and add singleton transactional generation state. Prefix registration, replacement, and deletion increment generation in the same transaction. Rolled-back changes do not alter visible generation. Registered-mode plan keys include generation; strict-mode keys do not.

Registry mutations are limited to the database owner, superuser, or designated pg-ripple administrator role. Revoke direct table DML. Validate prefix grammar and absolute expansion IRIs, including whitespace, control characters, terminators, and malformed percent escapes. Keep functions `SECURITY INVOKER` unless a narrowly reviewed definer is necessary; any definer pins `search_path` and fully qualifies objects.

### HTTP Contract

Add:

```text
POST /sparql/bindings
Content-Type: application/json
```

The request contains `query`, `bindings`, optional `prefix_mode`, optional replica policy, and an optional timeout that may only lower the server maximum. Only SELECT, ASK, CONSTRUCT, and DESCRIBE are accepted. Authentication, authorization, rate limits, OpenAPI registration, output negotiation, replica routing, and structured errors match `/sparql`.

Streaming-safe responses use the v0.134 pipeline. Invalid bindings and prefixes fail before stream headers. URL parameters and headers never carry binding maps.

### Stable Errors

Reserve PT0570-PT0579 for malformed binding objects, invalid/duplicate variables, unsupported terms, invalid literal metadata, out-of-scope variables, unsupported blank nodes, invalid prefix labels/IRIs, unauthorized prefix mutation, and parameterized Update. Run the PT collision checker before implementation and reassign the range if needed.

### Migration and Stable Manifest

`sql/pg_ripple--0.134.0--0.135.0.sql` must preserve existing prefixes, add owner/timestamp state, create and seed generation, revoke direct DML, install prefix functions and binding overloads where generated SQL does not, and support installations with populated registries.

Add to `api/stable-v1.json`:

- New SQL overloads and prefix functions.
- Prefix-mode and binding-limit GUCs.
- `POST /sparql/bindings` request, response, access, and error schemas.
- PT0570-PT0579.
- Strict-default prefix policy.
- Explicit exclusions for parameterized Update, blank-node/RDF-star bindings, multi-row binding tables, and stored-query catalogs.

Internal v0.134 stream functions remain excluded.

### Required Test Matrix

#### Parser and Algebra Tests

- URI, plain/typed/language literal, Unicode, quoting, escapes, limits, and every invalid shape.
- Subject, predicate, and object positions.
- FILTER, OPTIONAL, UNION, MINUS, VALUES, BIND, subqueries, aggregation/HAVING, property paths, named graphs, SERVICE policy, empty results, ASK, CONSTRUCT, DESCRIBE, and bound-variable projection.
- Existing no-binding calls produce unchanged results.

#### Security-Negative Tests

- Quotes, braces, semicolons, comments, SPARQL keywords, and SQL text inside literal values.
- IRI edge cases and attempted query termination.
- Prefix labels with syntax/whitespace and expansions with terminators/control characters.
- Unauthorized mutation and denied direct internal-table DML.
- Generated SQL text remains identical across values of the same binding shape.

#### Cache and Transaction Tests

- Same shape with 100 distinct values: one compilation miss then value-correct hits.
- Different binding sets/types produce distinct plans.
- Strict and registered modes produce distinct plans.
- Committed prefix change invalidates registered plans only.
- Rolled-back prefix change preserves generation and prior cache behavior.
- Concurrent readers observe prefix changes only after commit.

#### HTTP Tests

- JSON/CSV/TSV binding responses and N-Triples graph responses.
- Strict undeclared-prefix rejection, registered-prefix acceptance, and local override.
- v0.134 timeout, disconnect cancellation, pool cleanup, backpressure, and replica routing through `/sparql/bindings`.
- Invalid requests return structured PT errors before response streaming starts.

#### Fuzz Tests

Add `sparql_bindings_json` and `sparql_prefix_prologue` targets. They must never panic, generate malformed SQL, interpret values as syntax, change content outside the formal prologue, or overwrite local declarations. Run smoke jobs on pull requests for touched paths and retained-corpus jobs nightly.

#### Blocking Jobs

```text
regress-v0135-bindings
regress-v0135-prefix-mode
http-bindings
bindings-plan-cache
prefix-cache-invalidation
bindings-security-negative
bindings-fuzz-smoke
prefix-fuzz-smoke
api-stability-manifest
migration-0134-to-0135
fresh-vs-upgrade-0135
```

Every blocking job reports assertion counts and uploads raw evidence. No required check may skip successfully, use `continue-on-error`, or use `|| true`.

### Release Propagation

- v0.136 external audit covers binding parsing, absence of query/SQL interpolation, prefix privilege boundaries, prologue handling, transactional generation, and cache invalidation.
- v0.137 varies binding values, changes and rolls back prefixes, runs concurrent registry reads, and exercises binding streams, disconnects, deadlines, and replicas throughout the 72-hour workload.

### Exit Criteria

- No binding value enters SPARQL or SQL text.
- Positive, negative, cache, migration, HTTP, and fuzz matrices pass.
- Strict mode remains default; registered mode is deterministic, transactional, permission-controlled, and cache-safe.
- Query-local declarations win.
- Streaming and cancellation regressions pass through the binding route.
- Fresh and upgraded installations are equivalent.
- The complete public surface is CI-enforced in `api/stable-v1.json`.
- RC0 begins; no additional public query API enters v1 except release-blocker remediation.
